# sohocloud-protocol

وحدة Go المشتركة التي تُعرِّف **بروتوكول تنسيق الركيزة** لشبكة
SoHoLINK / Cloudy: التعرّف على العُقد، وسرد القدرات، وتوظيف
المهام؛ وهو البروتوكول الذي يتحدثه كل مُنسِّق وكل واجهة أمامية.

## النطاق

تحكم هذه الوحدة **التنسيق فقط**. وهي **ليست** اقتصاد أعضاء JFA —
فلا ضمان مالي (escrow)، ولا رصيد يُصدره الأعضاء، ولا عهد سمعة،
ولا سجل مختوم بالحوار، ولا فصل في النزاعات. تعيش هذه الأمور في كل واجهة
أمامية، وغيابها هنا مقصود.

إنها **ورقة في شجرة الاعتماديات**: لا تستورد أي وحدة أخرى من وحدات NTARI،
ولا تستورد شيئًا غير المكتبة القياسية لـ Go. فكلٌّ من SoHoLINK (المُنسِّق
المرجعي) وCloudy (واجهة أمامية) يستورد *هذه الوحدة*؛ ولا يُستورد شيء عبرها
في الاتجاه المعاكس. وهذه الخاصية — التي يفرضها رسم بياني للاستيراد لا النصّ
النثري — هي ما يمنع أي مُنسِّق واحد من أن يصبح محورًا يجب أن تمرّ الشبكة
كلها من خلاله (المشكلة المفتوحة رقم 7).

## الأدوار

تتحدث الواجهات الأمامية بالسطح الخاص بجانب العُقدة — `SubmitListing`
و`Heartbeat` و`PollJobs` و`Decline` و`ReportJob` و`Fees` — بالنيابة عن
الأجهزة التي يساهم بها أعضاؤها؛ أما المُنسِّقون فينفّذون واجهة `Coordinator`
ويُنسِّقون الواجهات الأمامية (ويُقيمون بينها اتحادًا). ولا يظهر الأشخاص على
السلك أبدًا: فهوية العضو شأن يخص الواجهة الأمامية، والهوية الوحيدة التي
تعرفها هذه الوحدة هي هوية عبء العمل — أي NodeID مع ارتباطه المعياري بـ
SPIFFE في `identity/`.

## البنية

```
version.go            protocol version (v0, unstable)
canon/                deterministic length-prefixed signing encoder
identity/             NodeID + the canonical SPIFFE binding predicate
listing/              CapabilityListing (node-signed)
liveness/             Heartbeat (node-signed)
employment/           Assignment (coordinator-signed); Decline, JobReport (node-signed)
fees/                 FeeDeclaration (coordinator-signed)
coordinator/          the Coordinator interface — the pluggable role, no algorithm
anchor/               STUB, not built — witnessed employment-claim layer (#6)
transport/httpjson/   reference transport; imported by no core package
vectors/              conformance test: regenerates and checks testdata/vectors.json
testdata/vectors.json cross-language conformance vectors (normative fixture; see SPEC.md §10)
```

## الحالة (بصراحة)

- **ما تم بناؤه:** أنواع الرسائل، وبايتات التوقيع المعيارية، والتوقيع
  والتحقق بـ ed25519، وواجهة `Coordinator`، ووسيلة نقل مرجعية عبر
  HTTP+JSON تحت `transport/httpjson`.
- **متجهات المطابقة:** الملف `testdata/vectors.json` هو الملف المرجعي
  المعياري (fixture) لمطابقة التنفيذات عبر اللغات — 25 حالة أوّلية،
  بالإضافة إلى جميع أنواع الرسائل الموقَّعة الستة مع بايتاتها المعيارية
  وتوقيعات ed25519 الخاصة بها. ويكون أي تنفيذ خارجي مطابقًا إذا — وفقط
  إذا — أعاد إنتاج هذا الملف بايتًا ببايت انطلاقًا من المدخلات نفسها
  (`SPEC.md` §10). ويعيد اختبار `vectors/` توليد الملف المرجعي من
  المُرمِّزات الحالية، ويُفشل عملية البناء عند أي انحراف.
- **وسيلة نقل مرجعية، لا البروتوكول السلكي:** الحزمة `transport/httpjson`
  اختيارية ولا تستوردها أي حزمة أساسية. ويجوز لأي تنفيذ مطابق أن يتحدث
  بهذه الرسائل عبر أي وسيلة نقل، وذلك بتنفيذ `coordinator.Coordinator`
  مقابل البايتات المعيارية الموثَّقة في `SPEC.md`.
- **بديل مؤقت (stub) غير مبني:** الحزمة `anchor/` — طبقة مطالبات التوظيف
  المشهودة (المشكلة المفتوحة رقم 6). وهي موسومة بأنها بديل مؤقت؛ راجع
  وثيقة الحزمة الخاصة بها.
